Credentials and safety

            
Keep your key on your device

            
Configure BROWSERBASE_API_KEY in your local environment or project secret manager. Never paste it into this page, chat, a frontend bundle, or source control. No project ID is required.

            

              
Use only authorized pages

              
The generated starter does not bypass access controls. Protected sites may require paid Browserbase capabilities, and some sites may prohibit automation.

            

          


          

            
Use a persistent context in your website

            
A website connection needs a server

            
This site is static HTML, so it cannot securely create Browserbase sessions by itself. To use the saved context in your own website, add a server-side endpoint in your existing application. That endpoint should authenticate the visitor, create the session with the same context ID and persist: true, and run the browser task on the server.

            
    
              
  1. Store BROWSERBASE_API_KEY as a secret on your server, never in page JavaScript.
    2. 
              
  2. Have your website call your own authenticated server endpoint; validate who may start a session.
    3. 
              
  3. Keep the session connection URL and browser control on the server. Do not return them to public visitors.
    4. 
              
  4. Reuse the intended context ID with persistence enabled so its browser state can carry across sessions, subject to Browserbase account and context settings.
    5. 
            

            
The code preview above is a local Node.js starter, not a live connection from this webpage. A static-site host alone cannot run the required server endpoint; deploy this integration in a backend you control.
