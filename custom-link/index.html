Original React Router idea

How the custom link decides it is active

In React Router v5, useRouteMatch checks the current route. When it matches, the component adds an active class and prints the marker before a normal Link.

function OldSchoolMenuLink({ label, to, activeOnlyWhenExact }) {
  const match = useRouteMatch({
    path: to,
    exact: activeOnlyWhenExact
  });

  return (
    <div className={match ? "active" : ""}>
      {match && "> "}
      <Link to={to}>{label}</Link>
    </div>
  );
}

Static demo note: the original snippet uses React Router v5 and BrowserRouter. This page mirrors its matching and active-state behavior with HTML, CSS, and hash navigation; it does not run React.

How the original custom link works

In the original React example, useRouteMatch checks the current route. Home requests an exact match, while About also matches nested routes.

function OldSchoolMenuLink({ label, to, activeOnlyWhenExact }) {
  const match = useRouteMatch({

  });

      {match && "> "}
      <Link to={to}>{label}</Link>
