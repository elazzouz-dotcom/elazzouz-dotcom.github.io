١ · اختر نموذج الاستمرارية

كيف تريد حفظ المشروع؟

دورة Hibernate / Resume عبر SSE

أنشئ مشروعًا واحفظ معرّف sandbox في قاعدة بياناتك. عند الاتصال، استأنف sandbox وأنشئ جلسة؛ عند إغلاق آخر اتصال SSE، أوقفه مؤقتًا بعد التأكد من ملكية المشروع.

  1. تحقق من هوية المستخدم وملكيته للمشروع قبل إنشاء الاتصال.
  2. تعامل مع إغلاق الاتصال مرة واحدة فقط، وراقب أخطاء التنظيف.
  3. استخدم مخزنًا مشتركًا أو leases عند تشغيل أكثر من نسخة من الخادم.

Git كمصدر استمرارية

استخدم مستودعًا تملكه أو لديك إذن بالوصول إليه. خزّن بيانات الاعتماد كأسرار خادمية، ولا تركّب repository URL مباشرة داخل أمر shell من إدخال المستخدم.

  1. تحقق من المضيف والمستودع والفرع عبر allowlist وسياسة واضحة.
  2. استخدم واجهة أوامر ذات معاملات آمنة بدل تركيب shell command نصيًا.
  3. اجعل الحفظ صريحًا وقابلًا للاسترجاع، ولا تعتمد على commit تلقائي عند كل disconnect.

Sandbox branches للتجارب

احتفظ بـ sandbox رئيسي خامد، وأنشئ نسخة عمل مؤقتة لكل معاينة أو اقتراح. الترقية تغيّر الأصل الذي يعتمد عليه المشروع وقد تستلزم حذف موارد أخرى.

  1. تحقق من المشروع والفرع وصلاحية المستخدم قبل كل عملية.
  2. حدّث قاعدة البيانات بمعاملة عند ترقية فرع إلى الأصل.
  3. لا تحذف الفروع الأخرى تلقائيًا قبل التأكد من النسخ الاحتياطي وسياسة الاحتفاظ.

نقاط مهمة

            
    
              
  • عدّادات الاتصالات داخل الذاكرة لا تعمل عبر أكثر من عملية أو خادم؛ استخدم leases أو مخزنًا مشتركًا وإغلاقًا آمنًا.
    • 
              
  • استمع إلى إغلاق SSE، واجعل التنظيف idempotent، ولا تعتمد على res.error وحده.
    • 
              
  • لا تنفّذ commit أو push أو delete تلقائيًا دون موافقة وسياسة نسخ احتياطي واضحة.
    • 
              
  • تحقق من ملكية المستخدم، وصحة المدخلات، وتوافق تفاصيل SDK مع إصدارك قبل كل عملية.
