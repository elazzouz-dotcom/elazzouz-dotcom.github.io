Why choose Inference Providers?

          
One consistent path across many AI providers.

          
Use one Hugging Face token and a consistent client experience while comparing models, task types, provider policies, latency, and cost in your own application.

Interface choice

          

            
Inference clients
Best when you need chat, image, embeddings, speech, or explicit provider selection.

            
OpenAI-compatible
Chat completions only; useful when migrating an existing OpenAI client.

            
Direct HTTP
Useful for custom request logic and environments without an SDK.

          

        

      

    


    

      

        

          
Practical recipes

          
Choose the lightest integration that fits.

          
Start with the official inference clients when you need more than chat. Use the OpenAI-compatible endpoint for chat-only migrations, and direct HTTP when you need complete control over request handling.

        

        

          

            ◎
            
Chat completion

            
Use an InferenceClient or the OpenAI-compatible route. Add a policy suffix such as :fastest, :cheapest, or :preferred to the model ID when supported by your workflow.

            
          

          

            ▧
            
Image generation

            
Use the task-specific inference client for text-to-image work. Review image dimensions, output format, provider availability, and expected cost before running it.

            
          

          

            ◌
            
Embeddings and speech

            
For embeddings or speech recognition, use the dedicated client methods rather than the chat-only compatibility endpoint.

            
          

        

        

          Production reminder:
           measure latency, throughput, quality, error rate, provider availability, and total cost with representative inputs. Keep HF_TOKEN in a trusted local or server environment; never place it in browser code.
